## 6. คำถามท้ายการทดลอง (Post-Lab Questions)

1. การใช้ **RF Signal Proximity (RSSI)** ร่วมกับ **HTTP Web Server** บน ESP32 แก้ปัญหาการฝากเช็กชื่อแทนกันในห้องเรียนได้อย่างไร?
```
ระบบเช็กชื่อจะผ่านก็ต่อเมื่อมือถืออยู่ใกล้ ESP32 จริง เพราะต้องมีค่า RSSI แรงพอ ใครฝากเพื่อนกดจากนอกห้องหรือจากที่ไกลๆ
สัญญาณจะอ่อนเกินเกณฑ์แล้วโดน Rejectedส่วน Web Server ทำให้กดยืนยันจากมือถือตัวเองได้ในคลิกเดียว แล้ว ESP32 ตรวจ MAC กับ RSSI ให้เลยโดยไม่ต้องมีคนเซ็นชื่อ
```
2. เหตุใดระดับเกณฑ์ RSSI ที่ `-55 dBm` จึงเหมาะสมสำหรับการระบุตำแหน่งอุปกรณ์ให้อยู่ภายในรัศมีโต๊ะปฏิบัติการ?
```
ที่ระยะ 1-2 เมตรรอบโต๊ะ RSSI มักอยู่ราว -30 ถึง -55 dBm การตั้งเกณฑ์ที่ -55 จึงครอบคลุมคนที่นั่งที่โต๊ะพอดี ถ้าตั้งหลวมกว่านี้ คนโต๊ะข้างๆ หรือนอกห้องก็อาจผ่านได้
แต่ถ้าตั้งแน่นเกินไป คนที่นั่งอยู่จริงอาจโดนปฏิเสธเพราะสัญญาณแกว่งตามสิ่งกีดขวางหรือท่าถือมือถือ
```
3. หากต้องการต่อยอดมินิโปรเจกต์นี้ในอนาคต ให้สามารถบันทึกข้อมูลการเข้าเรียนลงระบบ Cloud (เช่น Google Sheets หรือ Firebase) จะต้องเพิ่มส่วนเชื่อมต่อใดบ้าง?
```
ต้องให้ ESP32 ต่ออินเทอร์เน็ตได้ด้วย (โหมด AP+STA) เพราะตอนนี้เป็น AP อย่างเดียว แล้วส่งข้อมูลทั้ง MAC, เวลา, RSSI และผลผ่าน/ไม่ผ่าน
ด้วย HTTPS POST ไปที่ Google Apps Script หรือ Firebase ต้องเพิ่มการซิงค์เวลาด้วย NTP เพื่อให้ timestamp ถูกต้อง และทำตารางจับคู่ MAC กับรหัสนักศึกษา
เพื่อรู้ว่าใครเป็นใคร ถ้าจะให้ดีควรเก็บข้อมูลไว้ในเครื่องชั่วคราว เผื่อเน็ตหลุดแล้วค่อยส่งทีหลัง
```
