1. การใช้ **RF Signal Proximity (RSSI)** ร่วมกับ **HTTP Web Server** บน ESP32 แก้ปัญหาการฝากเช็กชื่อแทนกันในห้องเรียนได้อย่างไร?
```
บังคับให้อุปกรณ์ของผู้เรียนต้องอยู่ใกล้กับ ESP32 ในห้องเรียนจริงๆ (วัดจากค่า RSSI ที่ต้องสูงกว่าเกณฑ์ เช่น -55 dBm) จึงจะเช็กชื่อผ่าน
```
2. เหตุใดระดับเกณฑ์ RSSI ที่ `-55 dBm` จึงเหมาะสมสำหรับการระบุตำแหน่งอุปกรณ์ให้อยู่ภายในรัศมีโต๊ะปฏิบัติการ?
```
เพราะเป็นค่าความแรงสัญญาณที่สะท้อนว่าอุปกรณ์อยู่ภายในระยะใกล้ (ประมาณ 1-2 เมตร หรือในรัศมีโต๊ะปฏิบัติการ) ป้องกันการสแกนจากนอกห้องเรียนได้
```
3. หากต้องการต่อยอดมินิโปรเจกต์นี้ในอนาคต ให้สามารถบันทึกข้อมูลการเข้าเรียนลงระบบ Cloud (เช่น Google Sheets หรือ Firebase) จะต้องเพิ่มส่วนเชื่อมต่อใดบ้าง?
```
ต้องเพิ่มฟังก์ชัน HTTP Client (เช่น esp_http_client) เพื่อส่ง Payload ข้อมูลการเช็กชื่อผ่าน REST API ไปยัง Google Apps Script, Firebase หรือเซิร์ฟเวอร์ปลายทาง
```
