## 7. คำถามท้ายการทดลอง (Post-Lab Questions)

1. เหตุใดการใช้ **FreeRTOS Queue** จึงมีความปลอดภัย (Thread-Safe) มากกว่าการใช้ตัวแปรแบบ Global ในการรับส่งข้อมูลระหว่างสอง Task?
```
การใช้ FreeRTOS Queue มีความปลอดภัยมากกว่าตัวแปร Global เนื่องจาก Queue มีกลไกป้องกันการเข้าถึงข้อมูลพร้อมกัน ระดับ OS หากใช้ตัวแปร Global แบบปกติ ทาสก์หนึ่งอาจกำลังเขียนข้อมูลใหม่ลงไปในขณะที่อีกทาสก์กำลังอ่านข้อมูล ทำให้ได้ข้อมูลที่ผิดเพี้ยนหรือขาดตอน แต่ Queue ถูกออกแบบมาให้เป็น Thread-Safe โดยจัดการล็อคและคัดลอกข้อมูล อย่างสมบูรณ์แบบก่อนให้ทาสก์อื่นนำไปใช้
```

2. ค่า **Stack High Water Mark** มีประโยชน์อย่างไรในการตรวจวินิจฉัยปัญหาบั๊กในระบบเรียลไทม์ (RTOS)?
```
ค่า Stack High Water Mark จะแสดงถึง "พื้นที่ว่างของ Stack ที่เหลือน้อยที่สุด" ของทาสก์นั้น ๆ นับตั้งแต่เริ่มทำงาน หากค่านี้มีตัวเลขเข้าใกล้ 0 จะเป็นสัญญาณเตือนว่ากำลังจะเกิดปัญหา "Stack Overflow" ซึ่งจะทำให้โปรแกรมทำงานผิดพลาดหรือบอร์ดค้างและรีสตาร์ทตัวเอง การมอนิเตอร์ค่านี้จึงช่วยให้โปรแกรมเมอร์สามารถวินิจฉัยและปรับจูนขนาด Stack ในฟังก์ชัน xTaskCreate ให้มีความจุที่เหมาะสม ปลอดภัย และไม่สิ้นเปลือง RAM ของระบบ
```

3. หาก `vSensorTask` ส่งข้อมูลเร็วมาก (เช่น ทุก 10ms) แต่ `vNetworkTask` ส่งข้อมูลออก Wi-Fi ได้ช้า (เช่น ใช้เวลา 500ms) จะเกิดอะไรขึ้นกับ Queue และระบบจะรับมืออย่างไร?
```
ข้อมูลจากเซ็นเซอร์จะถูกส่งเข้าไปสะสมในคิวเร็วกว่าที่ถูกดึงออกไปประมวลผล ทำให้ในที่สุด "คิวจะเต็ม" เมื่อคิวเต็ม ระบบจะรับมือตามเงื่อนไขที่กำหนดไว้ในฟังก์ชัน xQueueSend():
- หากกำหนด Wait Time เป็น 0: vSensorTask จะไม่รอ และทิ้งข้อมูลเซ็นเซอร์ชุดใหม่นั้นไปทันที
- หากกำหนด Wait Time เป็น portMAX_DELAY: vSensorTask จะถูกบล็อกการทำงาน จนกว่า vNetworkTask จะดึงข้อมูลเก่าออกจากคิวไป ซึ่งจะทำให้ระบบการอ่านค่าเซ็นเซอร์ชะงักตามไปด้วย
```
